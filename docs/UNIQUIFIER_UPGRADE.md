# Безопасная модернизация уникализации

## Почему не включены все преобразования

Исходный проект `Hostlife22/video-uniquifier` предоставляет широкий набор
геометрических, цветовых, временных и аудиотрансформаций, но не рекомендует
включать их одновременно. Например, temporal_jitter намеренно вносит
выпадение/затемнение кадров, стереорасширение требует stereo, reverb может
снижать разборчивость речи, blend_b требует собственного B-roll, subtitles
требуют существующего SRT/ASS. Часть эффектов не совместима с HDR.
См. https://github.com/Hostlife22/video-uniquifier/blob/main/docs/transform_reference.md

Техническое изменение файла не является гарантией признания контента
оригинальным платформой или устранения ограничений рекомендаций.
Нужны права на исходные материалы и содержательная переработка, когда
несколько аккаунтов используют один ролик.

## Что включено в этой ветке

- Строгая проверка pHash: отсутствующая, некорректная или не соответствующая
  порогу метрика больше не даёт пройти в автопубликацию.
- Последний пресет strong больше не возвращается как успешный при провале QA.
- Таймаут внешнего процесса (переменная `UNIQ_TIMEOUT_SECONDS`, по умолчанию 900).
- Регрессионные тесты для контроля допуска.

## Что требуется до включения на рабочем сервере

1. Запустить `python -m pytest tests/test_uniq.py -q`.
2. Подключить исходные тестовые MP4 с обычной речью, титрами, музыкой,
   горизонтальным и HDR-видео (при наличии).
3. Проверить поворот и обрезку визуально. Патч геометрии требует проверки
   на разных пропорциях; не считать его доказанно корректным.
4. Сравнить два варианта одного источника друг с другом; одного pHash
   относительно исходника недостаточно.
5. Проверить нагрузку на CPU, время кодирования, качество речи и LUFS.
6. Не переключать текущую сборку на latest без миграции: сейчас Dockerfile
   фиксирует конкретный коммит прежнего движка и применяет патч.

## Следующий этап

Вынести взаимодействие с `video-uniq` в отдельный адаптер и протестировать
версию 2.1.x на отдельном окружении. Включить поддерживаемые preflight,
полный decode check, диагностические SSIM/VMAF и Chromaprint там, где они
доступны; сделать редакционные профили talking-head / educational / dynamic.
Преобразования blend/subtitles разрешать только при наличии материалов,
а экспериментальные/destructive эффекты — только после ручного просмотра.
