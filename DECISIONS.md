# Решения по проекту (одобрено 27.09.2026)

**Задача:** скачивать ролики студии с основных Instagram-аккаунтов, делать уникальную копию
под каждый аккаунт-сателлит и выкладывать по 3 поста в день в Instagram, TikTok и YouTube Shorts
через Postmypost. Управление — Telegram-бот.

1. **Контент** — собственный контент студии. Проверка чужих водяных знаков yt_uniquifier отключена.
2. **Источник** — только Instagram через `apify/instagram-reel-scraper`. Первый запуск — весь архив,
   затем раз в час только новые ролики. Видео скачивается сразу (ссылки Instagram живут недолго),
   запасной вариант — копия Apify (`includeDownloadedVideo`).
3. **Площадки** — Instagram, TikTok, YouTube Shorts через Postmypost; ролик идёт во все площадки.
4. **Маршрутизация** — правило «группа основных аккаунтов → её сателлиты»; один бренд = всё во всё.
   Правила меняются из бота.
5. **Уникализация** — yt_uniquifier (+ патч чёрных углов), своя копия на каждый аккаунт, 9:16 1080×1920,
   pHash-похожесть > 0.9 → переделать сильнее.
6. **Подписи** — из оригинала, без @упоминаний и ссылок; лёгкий рерайт Claude Haiku;
   кодовое слово защищено и проверяется; не распознано/пропало → одобрение в боте.
   Заголовок YouTube — первая строка, ≤100 символов.
7. **Расписание** — 3 слота в день на аккаунт (время задаётся), сдвиг ±15 мин; один ролик в разных
   аккаунтах — минимум через 2 часа; два ролика одного источника подряд в один аккаунт не ставятся,
   если есть альтернатива. Даты старта задаются из бота.
8. **Публикации создаются заранее** в Postmypost на 1–2 дня вперёд.
9. **Telegram-бот** — пульт (источники, аккаунты, слоты, пауза, очередь, «забрать сейчас»,
   одобрение) + уведомления (ошибки, очередь заканчивается, сводка). Доступ по белому списку ID.
10. **Инфраструктура** — одна Python-программа: бот + планировщик + обработка, SQLite, видео на диске,
    прямая загрузка файла в Postmypost. Из ТЗ берём статусы, защиту от дублей, идемпотентность
    публикаций, повторы, журнал событий. Без R2/Redis/PostgreSQL/FastAPI.
11. **Хостинг** — сначала ПК, потом VPS от 4 ядер.
12. **Первый запуск** — 1 источник, 1 аккаунт, только черновики.

Отложено: аналитика, умная обрезка по лицу, субтитры, A/B подписей.

## Этапы
1. ✅ Apify → скачивание → база с защитой от дублей
2. ✅ Обработка подписей (+ уже готовая уникализация)
3. ✅ Очередь и расписание по слотам → Postmypost
4. ✅ Telegram-бот
5. ✅ Перенос на VPS — Dockerfile + docker-compose (сборка образа не проверялась: на ПК нет Docker)

Всё кроме реальных API проверено тестами (89, `python -m pytest`). С настоящими Apify, Postmypost,
Telegram и Claude система ещё не запускалась — ждёт ключей (DEPLOY.md, раздел 1).

## Открытые вопросы (выяснятся на первом запуске)
- Postmypost: для Instagram проверено на живом API 27.09 — загрузка, `publication_type = 4` (Reels),
  черновик, чтение, поиск и удаление работают (удаление требует `account_ids`). API только на тарифе
  «Продвинутый». Для TikTok/YouTube формат проверится, когда их подключат в Postmypost.
- Подписи с «ссылка в шапке профиля» сейчас не трогаются — у сателлитов ссылки в шапке может не быть.
- Исходники роликов с диска не удаляются (архив 1000 роликов ≈ 10–20 ГБ) — очистку добавить при необходимости.
